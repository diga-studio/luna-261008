# log-error-rate-alerts

进程内日志错误率告警分析库（TypeScript，无接口层，数据保存在库实例内存中）。

## 能力

- `addRecords(records)`：批量追加请求记录（可任意乱序、时间戳可早于已有记录）。
- `deleteByTraceId(traceId)`：删除所有服务中匹配该 trace 的全部请求，返回删除条数。
- `queryAnomalyIntervals(service, startMs, endMs)`：查询指定服务在左闭右开范围
  `[startMs, endMs)` 内的全部异常区间，区间左闭右开、相接合并、跨界裁剪，精确到毫秒。

每条记录为一次请求：`{ timestampMs, service, status, traceId }`。同一 trace 可跨服务、
可含多条请求，每条独立计数。HTTP 状态码 500–599 计为错误。

## 异常判定

固定 15 分钟（900000 ms）滑动窗口。时刻 `t` 统计时间戳在 `(t - 900000, t]` 内的该服务请求：
请求在其时间戳处进入窗口，900000 ms 后离开。窗口非空且错误数占比**严格大于 5%** 才算异常
（恰好 5% 与空窗口均正常）。同一毫秒内的所有进入、离开共同决定该毫秒结果。

实现上把判定化为权重和：错误记 `+19`、成功记 `-1`，则
`错误率 > 5% ⟺ 20·errors − total > 0 ⟺ 权重和 > 0`，空窗口与恰好 5% 时权重和均为 0。
每条请求对其服务时间轴的 `[ts, ts + 900000)` 区间做一次区间加，异常时刻即权值为正的点集。

## 设计

- `src/treap.ts`：`WeightedIntervalMap`，以 run 划分整条时间轴的 treap（随机优先级、
  懒传播、子树 min/max 增广），支持 O(log n) 区间加与按输出大小的正权值区间枚举
  （只下探可能为正的子树）。节点存放在列式 TypedArray（SoA）中，百万级 run 下内存平坦。
- `src/analyzer.ts`：`AlertAnalyzer`，每个服务一棵时间轴；记录存列式数组，
  trace → 侵入式链表头，按 trace 删除即对链上每条记录做反向区间加。
  追加/删除单条记录 O(log n)，查询代价取决于异常段数而非记录数，因此历史修改、
  时间戳高度集中的场景也能在预算内完成。

## 构建与测试

干净机器（仅 Node.js）上：

```sh
npm install
npm test
```

测试包括：

- `test/analyzer.test.ts`：确定性场景——同一毫秒的进入/离开、恰好 5%、空窗口、
  1 毫秒异常、查询边界裁剪、相邻合并、晚到记录修改旧告警、跨服务 trace 删除、
  历史区间分裂等，每个场景都与独立重算（`test/helpers.ts` 暴力法）比对。
- `test/fuzz.test.ts`：确定性种子的随机增删查，逐次与暴力重算比对。
- `test/scale.test.ts`：规模测试——100 万条记录、90 天跨度、单服务承载全部记录、
  大量记录集中于同一 15 分钟窗口；初始加载后进行 1000 轮增删（每轮 ≤10 条，
  修改落在包括旧时间段在内的任意位置）+ 全量查询，断言总耗时 ≤10 s、
  峰值 RSS ≤768 MiB、每轮返回 ≤20 段，并在加载后/第 500 轮/结束后用
  O(n log n) 扫描线参考实现核对查询结果。运行日志会打印耗时与内存。
