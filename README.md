# SkillPulse 课表冲突引擎

纯内存、串行调用的 TypeScript 库。保证任何成功操作之后：同一教师 / 场地 / 学员不出现在时间重叠的两个场次中，且任何场次报名数不超过 capacity。

## 使用

```bash
npm install
npm test        # 编译 src + test 并运行全部测试（含 10 万场次规模测试）
npm run build   # 产出 dist/（含 .d.ts）
```

```ts
import { SkillPulseEngine } from 'skillpulse-scheduler';

const engine = new SkillPulseEngine();

// 1) 批量创建/替换场次（每批最多 200 个，id 在批内唯一）
engine.applyScheduleBatch([
  { id: 'A', instructorId: 'I1', venueId: 'V1', start: 0, end: 60, capacity: 10 },
]);

// 2) 报名 / 退出（重复加入、重复退出为空操作）
engine.setEnrollment('A', 'T1', true);

// 3) 读取当前场次与已确认学员（返回快照）
engine.getSession('A');
```

- 时间区间为左闭右开 `[start, end)` 的整数分钟，长度不限；首尾相接不算重叠。
- `capacity` 取值 1–50；批次超过 200 个、批内 id 重复、区间非法等输入错误直接抛异常。
- 替换场次保留其已确认学员；被替换场次的旧区间不参与冲突判断。
- 批次按"整批同时生效后的最终课表"判定：交换时间 / 场地不会因中间状态被拒绝。
- 任一违规则整个操作失败，所有场次、报名与索引保持操作前的状态。

## 诊断结构

失败返回 `{ ok: false, report }`：

- `report.overlaps`：最终课表中**至少一端属于本批次**、且**共享至少一项冲突资源**的重叠场次对（无共享资源的时间重叠不是违规，不列入）。每对按 `(场次1, 场次2)` 字典序排列，只报告一次；`resources` 依次为教师、场地、学员（学员按 id 排序），每个共享资源一条。
- `report.capacityViolations`：所有报名数超过 capacity 的场次，按场次 id 排序。
- 报名失败时同样返回该学员的全部时间冲突与容量问题，不在第一个冲突处停止。

## 复杂度与实现

设 N = 场次数 + 报名数，B = 批次大小，A = 批次涉及场次的已有报名总数，K = 诊断条数。

- **索引**：所有场次存于一棵按 `(start, id)` 排序、子树维护 `maxEnd` 的 treap（`src/intervalTree.ts`），插入 / 删除期望 `O(log N)`，重叠查询期望 `O(log N + k)`。每名学员另有一棵同构的小树，只含其已确认场次，更新与查询都是 `O(log n + k)`，不触碰该学员之外的任何数据。
- **applyScheduleBatch**：`O((B + A) log N + K)`。
  - 判定阶段只读不写：B 次全局索引重叠查询（跳过批内 id，旧区间自然失效）+ 批内按 start 排序扫描，得到全部冲突对；容量检查 O(B)。
  - 全部通过才提交：B 次全局索引增删；仅当区间变化时，对该场次携带的每条报名（合计 A）做一次学员索引增删。
  - 原子性来自"先判定、后提交"，不复制任何状态。
- **setEnrollment**：`O(log N + K)`。查询该学员自己的区间树得到全部冲突；容量检查 O(1)。
- **空间**：常驻 `O(N)`；单次操作的临时空间为 `O(B + A + K)`，与 N 无关。
- 冲突对的共享学员取两个学员集合中较小者做哈希交集，每条共享学员都是一条诊断输出。

规模测试（`test/perf.test.ts`）：10 万场次、30 万报名集中在 10 教师 / 10 场地 / 300 热点学员上，2000 轮"小批次调期 + 报名增删"（共 2000 批次、1.6 万报名操作）在本机约 0.3 秒完成（造数过程不计入）。
