# phrase-translate-core

本地短语表翻译内核（TypeScript）。只处理一个语言对：调用方提供词条和从
HTML 中抽取的文本节点字节流；HTML 解析、译文转义和缓存不属于本组件。

## API

```ts
import { compile, translate } from "phrase-translate-core";

const table = compile([{ source: "你好", target: "Hello" }]);   // 编译一次
for await (const bytes of translate(table, byteStream)) { ... } // 多次复用
```

- `compile(entries)`：每条词条含非空 `source` / `target`，`source` 不重复。
  产出可复用的编译词表。
- `translate(table, chunks)`：输入是异步 UTF-8 字节流（每块 ≤ 4096 字节，
  块边界可落在多字节字符内部），输出是异步 UTF-8 字节流。

## 匹配语义

在当前输入位置选择从这里开始的最长 `source`，输出其 `target` 并消费对应
输入；无匹配则原样保留一个 Unicode 码点。长度按码点计；大小写、空白、
标点精确匹配；译文不再参与匹配。无论输入如何分块，输出与整段文本做
从左到右最长匹配的结果逐字节相同，且不会等整段输入到齐才开始输出。

## 实现

编译期把全部 `source` 建成 **Aho-Corasick 自动机**（trie + failure 链，
码点为字母表）。转换期单遍扫描，维护两个指针：

- `state`：标准 AC 状态（带 failure 转移），表示已扫描输入的最长
  “是某词条前缀”的后缀。
- `walk`：从首个未提交位置（commitPos）开始的纯 trie 路径节点。它恰好是
  `state` 的 failure 链上深度等于“未提交长度”的节点，因此可以增量维护：
  存活时走子边，提交后沿 failure 链重定位。`walk` 路径上最深的终结节点
  就是 commitPos 处的最长命中。

提交规则：命中在“不可能再变长”时立即提交（walk 死亡、未提交长度达到
L、或输入结束）；walk 死亡且无命中时当前码点立即原样输出。已读入但未
产出的源文本始终 < L 个码点（远小于 4L+4096 的上界），调用方暂停供给时
已确定的结果已经产出。

## 复杂度

设 M 为词条总长度，N 为输入长度，R 为输出长度，L 为最长 source 长度
（均按码点计）：

- 编译时间 / 词表空间：O(M)。
- 每次转换时间：O(N + R)，均摊。AC 转移是标准的均摊 O(1)；提交后沿
  failure 链重定位的步数不超过该次提交消费的码点数（可证明整段转换中
  所有重定位总步数 O(N)）。
- 转换额外空间：O(L)（未提交码点缓冲）+ 当前输入块；不积存完整输入、
  完整输出或已处理前缀。

### 为什么不会退化

- **不会反复长前缀试探**：前缀复用全部沉淀在自动机结构里。输入为长串
  `a`、source 为 `a^8191 b` 时，每个新码点只做一次 failure 回退加一次
  子边命中（均摊 O(1)），而不是从每个位置重新试探 8191 长的前缀。
- **不会候选命中数量爆炸**：每个位置只保留 walk 路径上的最深终结节点
  一个候选（O(1) 空间）。source 为 `a^1..a^1999` 时，虽然每个位置都有
  1999 个命中结尾，但贪心只需要 commitPos 处的最长者，浅层命中被同起点
  的更深命中直接覆盖，从不枚举。

## 测试

```sh
npm install
npm test
```

只依赖 Node.js（≥18）与 devDependencies 中的 `typescript` / `@types/node`，
`npm install` 后 `npm test` 即可跑通：先 `tsc` 编译，再用 Node 内置测试
运行器执行 `dist/test/*.test.js`。

测试覆盖：共享前缀 / 包含关系 / 多字节词表在整块、逐字节、随机边界三种
供给下与朴素参考实现逐字节一致；输入结束时长词组未完成但短词组已命中；
空词表；编译结果复用；两组 ≥1MiB 的可重复压力测试（记录编译与转换耗时）；
以及供给方暂停时转换仍能推进的测试。
